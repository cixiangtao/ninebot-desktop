# 韭号出行

一个本地只读的九号车辆与骑行数据客户端。桌面端随包提供经过固定哈希校验的 ninecli 0.1.7，Electron 主进程负责运行时生命周期、领域解析、缓存与导出；支持自有/共享车辆与多车辆切换，并按账号关系展示车辆激活日期或获得共享权限的日期；区分主电源与 ACC，逐组查看单/双电池的类型、电量、评分、温度、电压、循环次数和 BMS 说明，对比智能/精细/基础三种续航估算并展示充电剩余时间与预计完成时间，还可按需监看只读状态变化；按年份和月份浏览历史，导出年度统计或带极速依据的月度逐次清单，通过全年每日里程热力图查看连续骑行和活跃规律，把官方电自详情页没有展示的极速、单次能耗、电量消耗、平均能耗和骑行日背景直接可视化，并支持同月行程对比以及 GPX、CSV、JSON 三种格式导出。

## 下载

[GitHub Releases](https://github.com/cixiangtao/ninebot-desktop/releases) 提供 macOS Apple Silicon 的 DMG/ZIP、Windows x64 的 NSIS 安装程序/ZIP，以及统一的 SHA-256 校验清单。安装包已经内置 ninecli 运行时，普通使用者无需另装 Python、uv 或 ninecli。当前 macOS 包采用 ad-hoc 签名且尚未经过 Apple 公证，Windows 包尚未进行 Authenticode 签名，因此 Release 会标记为 prerelease；Gatekeeper 或 Microsoft Defender SmartScreen 可能阻止直接打开，请只在理解并接受风险时安装。

本项目不是九号官方产品，也未获得九号品牌或商业背书。

## 开发

源码开发只需要 Node.js 24 和 pnpm 10。`pnpm dev` 会准备并校验本机平台的 ninecli 运行时后启动 Electron；生成目录不会进入 Git。

```bash
pnpm install
pnpm dev
```

默认登录信息保存在 Electron `userData/ninebot` 目录。首次启动时如果检测到旧版 `userData/ninecli`，会只读复用其中可迁移的会话和车辆元数据；开发时也可以显式复用已有的九号配置目录：

```bash
NINEBOT_CONFIG_DIR=/absolute/path/to/ninecli-config pnpm dev
```

仓库保留 Node.js/TypeScript 协议研究工具用于离线 parity 和响应解析测试；生产桌面端以随包 ninecli 为主，车辆列表与月度补充分页使用 TypeScript 协议桥。协议记录器仅监听本机且默认不保存 Body 原文，使用方式和私有样本边界见[九号协议研究计划](docs/PROTOCOL_RESEARCH.md)。

正式应用以 ninecli 为主运行时。Electron 只允许 `whoami`、`login`、`login-code`、`vehicles`、`status`、`battery` 和 `travel` 这一组只读或认证命令，并在执行前验证随包二进制；运行时输出先在主进程解析为脱敏领域对象，再进入 IPC。ninecli 的 `travel --month` 只提供首屏逐次明细，因此主进程在检测到截断时，使用窄范围 TypeScript 协议桥重新分页读取完整月份（包含第一页）。登录、会话、状态、电池和轨迹详情仍由 ninecli 提供；车辆列表使用 TypeScript reader。分页缺失、重复或失败会明确报错，不静默导出首屏。

SDK 新增 `@jiuhao/ninebot-client/auth-node` 两阶段认证入口：先取得 Passport 令牌，再调用加密 business login，以业务响应的 `data.uid` 建立完整会话后才保存；Passport 中的 `uid` 不作为业务 UID。入口包含刷新、文件存储和退出清理，退出会同时删除新旧两种令牌文件，避免重启后恢复旧会话；新设备使用已观察到的 Android 协议默认元数据。本地模拟服务端已覆盖认证闭环与失败路径，用户提供的一次新密码登录、Business、资料及恢复已通过，但刷新返回90002，完整认证验收未通过；Electron 已提供 `NINEBOT_AUTH_SOURCE=sdk` 显式入口，默认运行时未切换，详见[一期认证验收](docs/AUTH_PHASE1.md)。用法与兼容变化见 [SDK 文档](packages/ninebot-client/README.md)。短信请求仍遵循服务端人机校验边界。

最小真实认证验收可运行 `pnpm protocol:auth -- --auth-only`，不读取车辆或行程；完整只读验收可运行 `pnpm protocol:auth -- --month=202609`，按终端提示输入账号、区号和不回显的密码。工具在新的临时目录中完成两阶段登录、资料读取、会话恢复、强制刷新及刷新后恢复，再读取选定车辆的状态、电池、月度首屏和一条行程详情，最后退出并检查会话无法恢复；正常结束或处理失败后删除临时目录。默认检查电自，电摩使用 `--service=motor`，多车辆可指定 `--vehicle-index=1`。只输出阶段结果与计数，无车或月份无行程时标为未覆盖并以退出码 2 结束；完整通过为 0，失败为 1。此工具不依赖已有 ninecli 登录态，范围及机器输入方式见[认证验收说明](docs/PROTOCOL_RESEARCH.md#真实-sdk-认证验收)。

候选请求默认最多等待 15 秒；VPN 或上游较慢时可通过 `NINEBOT_CANDIDATE_TIMEOUT_MS` 调整为正整数毫秒，超过 120 秒会按 120 秒执行，空值或非法值回到 15 秒。超时后该次读取按 SDK 错误边界结束，不会偷偷切换到 ninecli，也不会改变数据源开关或会话凭据。

SDK 根入口同时导出 `createNinebotCandidateSessionClient` 和 `createNinebotFetchCandidateSessionClient`，把同一份内存会话元数据适配为车辆列表、status、battery、月度和详情五类只读调用；fetch 工厂默认使用已验证的九号服务地址，也支持局部覆盖 origin（未覆盖的服务仍保留默认地址）和 fetch 实现。它不提供登录、令牌文件读写或车辆控制；调用方负责会话生命周期和凭据保护，退出登录时可调用返回对象的 `clear()` 阻止后续请求并释放会话引用，可通过 `@jiuhao/ninebot-client/candidate-session` 单独导入。协议回放或测试可注入 `clock`、`nonceFactory` 和 `requestIdFactory`，生产环境默认仍使用系统时间与安全随机值。

为后续 Web、React Native 或其它移动端复用生命周期，SDK 另提供不导入 Node 加密实现的 `@jiuhao/ninebot-client/candidate-session-core`。调用方注入各平台自己的车辆、telemetry 和 travel 加密客户端后，可共享字段组装、request-id 传递、AbortSignal 取消和 `clear()` 会话清理；没有 Web Crypto 的运行时还需注入 `nonceFactory`。这只是运行时编排层，不声称已经提供浏览器或移动端加密实现。

SDK 还提供 `@jiuhao/ninebot-client/crypto-web`，以 Web Crypto 和纯 TypeScript 实现提供 Base64、MD5、AES-CBC、RSA PKCS#1 v1.5、四段响应 key mixer 与随机材料原语；`crypto-web-codec` 在其上组装已观察的请求外壳和响应解密链，`transport-web` 则提供保留二进制响应、取消和超时的 Fetch 边界。它为后续移动端 service client 铺路，尚未接管 Electron，也不等同于浏览器端完整九号协议客户端。

轨迹页使用 MapLibre GL JS 渲染，并加载 OpenFreeMap 的 Positron 在线底图。路线按照逐点速度从蓝色、青色、黄色、橙色到红色分段着色，回放支持 0.5×、1×、2×、4× 连续倍速；速度曲线支持点击、拖动以及方向键、Home、End 精确定位，并与地图位置、当前速度和时间共享同一回放状态。页面还会在本地按 GPS 轨迹段距离汇总五档速度区间，点击任一区间可定位到该区间最快轨迹段。侧栏保留整月次数、里程与能耗汇总，并明确显示当前可选择的行程条数；详情卡会展示本次能耗（Wh）和电量消耗（%）。同月行程对比会按需再读取一条详情，并排展示轨迹实测极速、平均速度、里程、用时、能耗、电量消耗及五档速度里程占比。差值只描述数据变化，不判断骑行好坏，返回后保留原行程的回放位置。无需 API Key，断网、VPN 或底图服务异常时会在 10 秒内回退到使用同一套速度颜色的本地轨迹画布，速度曲线和回放仍可使用。`status` 原始响应可能包含位置；普通设备读取会在 Electron 主进程解析时丢弃坐标，不把它交给页面。用户在车辆位置页明确确认后，客户端才把新读取的坐标交给页面并加载位置区域瓦片；停止显示或切换车辆会立即清除页面中的坐标。共享车辆若通过 `permissions.see_location` 明确拒绝位置访问，客户端会剥离坐标、不创建地图、不请求瓦片，并提示让车主调整共享权限后重新检查。

在线地图默认使用 SDK telemetry 返回的坐标原值。中国大陆范围内可显式切换本地 `GCJ-02 → WGS84` 校准预览并查看大约位移，用道路贴合情况判断坐标基准。预览只改变地图覆盖物副本，不修改原始轨迹、速度、里程、统计或导出，也不调用外部坐标转换服务。

## 只读能力覆盖（ninecli）

| 九号只读能力                                  | 客户端状态   | 说明                                                            |
| --------------------------------------------- | ------------ | --------------------------------------------------------------- |
| `whoami`、`login`                             | 已接入       | 校验会话、显示脱敏账号标识与密码登录                            |
| `vehicles`                                    | 已接入       | 自有/共享切换、激活/授权日期、智能服务剩余天数及临时 ID 隔离    |
| `status`                                      | 已接入       | 主电源、ACC、锁车、续航、基础电量回退、充电时间及按需状态监看   |
| `battery`                                     | 已接入       | 单/双电池类型、电量、温度、电压、循环次数、评分与 BMS 说明      |
| `travel --month`、`travel --detail`           | 已接入       | 日历、月/年统计、逐次清单、极速校验、平均能耗、回放、对比及导出 |
| `login-code`                                  | 受限接入     | 支持发送与提交验证码；若触发网易易盾则明确提示改用密码登录      |
| `mcp`、`serve`                                | 不嵌入客户端 | 桌面端直接使用受控领域桥接，避免开放明文 REST 或任意工具调用面  |
| `bell`、`buck`、`engine-start`、`engine-stop` | 明确排除     | 会改变车辆状态，不进入只读客户端白名单                          |

年度统计按 3 个并发批次读取月份，不加载 GPS 轨迹。查看当前年份时，请求范围会与“截至本月的近 12 个月”去重合并，因此跨年趋势不需要再次读取；历史起点之前的月份直接跳过。月份先由 ninecli 读取，超过首屏的月份由主进程协议桥补全分页。韭号出行用顶层汇总计算全年总量、平均能耗和活跃天数，并把每日里程做成可筛选的月度骑行日历；完整汇总与逐次明细分别校验覆盖范围。

统计页还会把已加载的每日里程排列成年度活动热力图，并在本地计算最高里程日、最长连续骑行和最常骑行的星期。历史起点之前、今天之后以及上游缺失的日期都不会被伪造为零里程；点击有里程的日期只加载并返回对应月份的列表，继续选择某条具体行程后才读取 GPS 详情。

可选行程中的 `day_total_mileage` 与完整每日里程数组采用同一口径。韭号出行会在详情页展示当天累计里程和本次行程所占比例；自动分页后的全部行程会参与一致性校验。字段缺失、无效或小于本次里程时保持不可用，不用矛盾数据计算占比。单次 GPX、CSV、JSON 导出也会保留该日里程，其中 JSON 使用 schema v2。

`vehicles` 返回的 `actived`、`active_date` 和 `auth_date` 会先在主进程校验状态、Unix 秒范围与先后顺序。自有车辆只展示激活日期，共享车辆只展示当前账号获得共享权限的日期；显式未激活、缺失、越界或早于激活时间的授权日期不会进入页面，也不会用另一个日期冒充。

月度趋势可以在里程、次数、平均单次里程、能耗、活跃天数和平均能耗（Wh/km）之间切换；当前年份还可在“自然年”和“近 12 月”之间切换，连续查看跨年数据。平均单次里程使用完整月度总里程除以完整月度次数，不受分页明细数量影响；所有值都来自统计页已经读取的 `travel --month` 汇总，不会因为切换指标或时间范围重复调用九号接口。历史起点之前的月份会禁用，上游缺失的能耗或每日里程保持为“不可用”，不会补零；点击任意已发生月份的柱形或月度明细，会进入该月行程列表，但仍不会自动读取第一条 GPS 轨迹。年度 CSV/JSON 导出仍严格使用当前所选自然年，不会把跨年趋势月份混入年度口径。

年度统计加载完成后可导出 CSV 或 JSON 摘要。schema v2 包含车辆显示名称、年份、数据起点、年度总量与平均值、完整月度总量与平均值、每日里程，以及汇总是否完整、可选明细是否被截断等覆盖标记；CSV 首条数据是可直接用于 Excel 的年度汇总行，JSON 保留年/月/日层级供编程、备份和 AI 分析。导出不会额外请求行程详情，也不包含 GPS、车辆 SN 或九号内部行程 ID；任一活跃月份缺失能耗或活跃天数时，相应年度值保持为空。

轨迹侧栏可以把当前月份导出为 CSV 或 JSON 月度清单。文件保留完整月总次数、里程、时长、能耗、每日里程和分页补全后的全部逐次行程，并披露明细覆盖范围。逐次记录包含时间、里程、时长、能耗、电量消耗、骑行日累计和平均速度，但不包含 GPS、车辆 SN 或九号内部行程 ID。极速同时保存接口声明值、轨迹采样值、最终显示值和依据类型：未经轨迹校验的旧 `25 km/h` 摘要使用 `unverified-capped` 并把最终显示值留空，校验后才使用 `track` 结果。

`travel --month` 的 `first_time` 在活跃月、空月和历史起点之前都稳定返回该车辆的首条骑行时间。韭号出行用它标出“数据从哪一天开始”，禁用更早月份，并在年度统计中跳过起点前的空查询；这既减少 ninecli/九号接口调用，也避免把“车辆还没有数据”误解成普通的零骑行月份。

九号旧月份的月度摘要可能把 `speed` 固定返回为 `25 km/h`，但行程详情的逐点轨迹仍保留真实速度。韭号出行在详情页始终优先用轨迹点计算峰值；列表在获得轨迹依据前只显示“待校验”，不把 `25` 冒充成真实极速。检测到 `25` 与轨迹不一致时会明确标为旧摘要占位值并忽略。轨迹侧栏还提供显式的“本月极速校验”：按 3 路并发读取 SDK 自动分页得到的本月行程详情，把逐行极速纠正为轨迹采样值。批量桥接只向页面返回匿名行程 ID、接口极速和采样极速，不返回经纬度或完整轨迹；切月、切车或退出登录会立即丢弃结果，单条详情缓存仍只存在于当前主进程内存。

ninecli 0.1.7 自带的行程文本格式将 `ec` 标注为能耗（Wh），将 `used_electricity` 标注为电量消耗（%）。韭号出行按这两个单位展示和导出，并在 `ec` 有效且里程大于 0 时计算平均能耗（Wh/km）；详情和同月对比都使用同一规则，缺失能耗或零里程显示 `—`，不会伪造为零。差值保持中性，不把更低的能耗自动解释为更好的骑行。

车辆状态中的顶层 `pwr` 与 `status.loc.acc` 含义不同：前者是 ninecli 的主电源状态，后者是 ACC 状态。韭号出行分别展示两者，不再把 ACC 冒充成车辆电源。`battery_type=1` 按 ninecli 文本输出映射为锂电；座桶锁、内部续航选择等缺少稳定语义的枚举仍不进入页面。真实响应中的 `battery_count` 可能为 `0`，同时却返回一组有效电池；BMS 支持标记也可能为 `false`，同时仍返回有效循环次数。因此韭号出行不把这两个字段解释为电池组总数或循环统计是否可用，继续以实际 `battery_list` 和有效值为准。

设备页的“自动监看”默认关闭。用户主动开启后会立即绕过缓存读取一次 `status` 与 `battery`，此后每 60 秒最多再读取一次，并只比较剩余电量、车辆锁、主电源、ACC、充电状态和两个数据域的可用性。离开设备页、隐藏窗口或已有状态请求进行中时不会发起自动读取；切换车辆或退出账号会关闭监看并清空变化记录，关闭监看会停止轮询但保留最后一次结果供核对。监看仍复用普通设备快照的脱敏契约，不向页面传递 SN、坐标或 ninecli 原始响应，也不把变化历史写入磁盘。

设备页把 `status` 与 `battery` 视为两个独立只读数据域：其中一个临时失败时仍展示另一个已经成功的数据，并明确提示不可用区域。电量优先采用独立 `battery` 诊断读数；若该域失败，则回退到 `status.dump_energy`，继续保留基础电量、续航和车辆状态，并在电量环内标为“车辆状态回退”。两个接口同时可用但相差至少 5 个百分点时，页面并列披露两者并继续优先使用诊断读数。其他缺失项保持为 `—`。只有两个接口都失败，或出现登录失效、运行时缺失、完整性校验失败等安全错误时，才让整页读取失败。

为减少重复调用，设备快照、月度列表和行程详情只在当前 Electron 会话的主进程内缓存解析后的领域对象，默认有效期分别为 15 秒、2 分钟和 10 分钟；相同并发请求会合并。缓存不写磁盘、不保留 ninecli 原始响应，退出登录、成功刷新车辆列表或退出应用后失效；页面中的手动刷新会绕过已完成缓存并重新查询。轨迹指标卡上的刷新按钮只重取当前 `travel --detail`，不会重拉整月；成功后保持当前行程和相对回放位置，失败时保留上次成功数据。演示数据不会伪装成真实刷新，因此按钮保持禁用。

macOS Apple Silicon 与 Windows x64 的打包、ASAR 完整性校验、安全熔断、崩溃恢复、产物校验和成品启动冒烟已经接通。Windows 还会静默安装到临时目录，从安装结果再次启动验收并确认卸载程序存在。当前 macOS 包采用 ad-hoc 签名，Windows 包未签名；稳定公开发布仍需相应平台签名和公证/信誉。完整说明见 [发布说明](docs/RELEASE.md)。

项目不包含遥测或分析上报；账号、令牌、车辆、位置、轨迹和第三方网络请求的具体边界见 [隐私说明](PRIVACY.md)。

## 检查

```bash
pnpm check
pnpm build
pnpm package:mac:dir
pnpm package:mac:local
pnpm package:win:local
```

`pnpm check` runs the Electron TypeScript typecheck, lint, formatting and test
gates. The protocol research package remains a development-only workspace
dependency and is not loaded by the production main process.

`package:mac:local` 会生成 DMG 和 ZIP，`package:win:local` 会生成 NSIS 安装程序和 ZIP；两者都会从成品启动自动化冒烟，但都不是正式签名包。Windows 打包与验收必须在 Windows x64 上运行。

当前仓库采用 `UNLICENSED`：源码公开可见不等于授予复制、修改或再分发许可。后续如决定开放协作，会另行加入明确的开源许可证；项目所使用的第三方依赖仍分别遵循其各自许可证。

## 安全边界

- 渲染层只能调用版本化、面向领域的桥接：登录、退出、运行时诊断、车辆列表、脱敏后的车辆/电池状态、行程列表、行程详情和用户主动触发的文件导出；不能传入任意命令或文件保存路径。
- Electron 安装包通过 `extraResources` 包含对应平台的 ninecli 原生二进制；业务请求只经过主进程的固定命令适配器，运行时不要求用户安装 Python、uv 或 ninecli。
- `status` / `battery` 仅对普通上游临时错误做分区降级；认证、人机验证、二进制缺失、平台不支持或完整性失败继续按安全错误中止，不会用部分结果掩盖。
- SDK 配置目录权限固定为 `0700`，已知配置和令牌文件固定为 `0600`；设置页可退出账号并按文件名清除令牌和车辆缓存。
- 车辆 SN、实时状态中的经纬度和上游 `travel_id` 仅保留在 Electron 主进程，页面只接收会话内的临时编号与脱敏后的状态数据。
- `whoami` 返回的手机号、邮箱、用户名、UUID、头像和第三方 OpenID 原文会在主进程中丢弃；页面只接收带星号的账号标识与是否设置密码。
- `status` 原始响应可能包含 `loc`。普通设备读取只在主进程解析所需状态并丢弃坐标，不把原始响应或经纬度交给页面；位置授权前不创建车辆地图，也不发起位置区域瓦片请求。授权后独立桥接会重新查询状态，页面只接收共享位置权限，以及允许情况下的坐标、锁车和 ACC 状态。显式拒绝时主进程剥离坐标，授权只保留在当前会话和当前车辆中。
- 设备快照、月度列表和行程详情缓存仅存在于主进程内存，保存的是解析后的领域对象而不是九号原始响应；手动刷新绕过已完成缓存，退出登录、成功刷新车辆列表或应用退出后清空。
- 不实现鸣笛、开座桶、启动或熄火能力。
- ninecli 仅允许固定的只读与认证命令，生产客户端不暴露车辆控制命令、任意 argv 或 shell。
- 默认旧入口的密码和短信验证码在 ninecli 子进程参数边界内传递，显式 SDK 入口则使用内存调用；项目不记录这些参数，也不把凭据写入渲染层日志。
- 短信登录不会绕过九号的网易易盾人机验证。若服务端返回 `90202 / send code need verify`，客户端会给出受控提示并停止，密码登录仍是默认入口，但真实新登录与刷新尚待验收。
- 在线底图会向 OpenFreeMap 请求当前视野的样式、瓦片、字体和图标，因此服务方能推断正在查看的大致区域；应用不会把完整轨迹 JSON、九号账号、令牌或车辆 SN 作为地图请求参数发送。
- 轨迹线、起终点与回放点只在本地 MapLibre 图层中绘制；若不希望产生第三方瓦片请求，可在无网环境使用自动回退的本地轨迹画布。
- GPX、CSV 和 JSON 导出都包含精确经纬度、时间、逐点速度、本次能耗、电量消耗和骑行日里程。渲染层不能指定写入路径；只有用户在系统保存窗口中确认后，主进程才会写入所选位置，并且不会把目录路径回传给页面。
- 年度摘要导出采用更小的数据边界：只包含车辆显示名称、年/月总量与平均值、每日里程及完整性标记，不包含 GPS、车辆 SN 或九号内部行程 ID；每日出行规律仍可能属于敏感个人信息。
- 月度清单导出同样不包含 GPS、车辆 SN 或九号内部行程 ID，但会包含自动分页后的全部逐次时间、里程、能耗和极速依据；完整月汇总与逐次明细分别披露覆盖范围。
- 九号接口没有声明经纬度基准，默认仍按接口原值绘制。中国大陆范围内可主动启用本地 `GCJ-02 → WGS84` 校准预览，对照道路后再判断；该会话状态不改写 ninecli 数据、统计或导出。
- 打包后的渲染页面通过受控的 `ninebot-desktop://app` 协议加载，只允许读取 ASAR 内的 renderer 目录；不授予 `file://` 页面读取本机任意文件的额外权限。
