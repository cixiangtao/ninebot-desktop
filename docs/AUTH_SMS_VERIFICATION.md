## SDK 与桌面的职责

SDK 的 `requestSmsCode({ areaCode, phone, validate? })` 允许宿主传入本次用户完成验证得到的结果。未传结果时，原发码请求正文和签名不变；传入时，将原值加入正文和签名。SDK 不自动重试挑战、不保存验证结果、不把它放进短信验证码消费请求。当前本地输入边界为非空字符串、最多 4096 字符。

`ninebotSmsVerification` 提供已观察到的验证码配置：`provider: "netease-yidun"`、上述 `captchaId` 和 `https://cstaticdun.126.net/load.min.js`。这只是宿主接入配置，SDK 核心不会加载脚本、打开窗口或请求验证服务。各宿主仍需验证自己的组件及网络环境。

桌面端在明确的人机验证拒绝后打开独立验证窗口，使用隔离会话，不向验证页面暴露应用的账号、车辆或文件操作 bridge。用户成功完成验证后，针对原请求最多进行一次携带结果的发码重试。重复挑战、网络错误和服务端拒绝继续报错，不循环发码。

供应商组件的模板渲染使用 `new Function`，因此独立验证码窗口的 CSP 允许 `unsafe-eval`，并允许来自限定供应商域名的脚本与样式资源。该设置只用于无账号资料的隔离验证窗口，主应用页面的 CSP 不变。窗口保持 sandbox、context isolation、禁用 Node 集成，仅暴露完成、取消、失败三个固定回调；禁止新窗口、页面跳转、下载和权限申请，关闭后清理会话存储与连接。组件初始化同步抛错或专用 preload 加载失败时，窗口及时退出并向主页面返回固定错误，不等待超时或继续发码。

改手机号或区号、切换登录方式、关闭登录面板时，应取消这次验证流程；主进程必须在继续发码之前核对请求是否仍有效。只屏蔽渲染层的迟到“已发送”提示不够。已经发送到官方服务器的请求无法通过关闭窗口撤回。

## 验收边界

SDK 请求和签名测试使用合成手机号、验证结果及响应，覆盖显式重试、非法输入在发送前拒绝，以及验证结果不持久化、不复用。真实 Electron 的合成组件回归已覆盖窗口关闭、取消、改号、迟到结果、初始化抛错、携结果单次重试与短信登录；该回归不访问真实网络。测试通过不证明官方服务会接受当前宿主产生的验证结果。

2026-10-27 的真实组件只读检查已显示易盾拼图与滑块，脚本、配置、图片请求成功，隔离窗口无应用 bridge 或 Node 全局。未拖动滑块、未取得验证结果、未请求短信或登录账号。可运行 `pnpm run build` 后执行 `node scripts/qa-sms-widget.mjs --live` 重做这一不涉及账号的组件检查。

真实验收由用户在 **SDK 模式**下自行操作；普通默认桌面运行时仍可能使用旧的 ninecli，不能将旧路径的结果记作 SDK 验收。需要逐项确认：

1. 选择短信登录并发码，出现验证要求时能够展示正常验证组件。
2. 用户完成验证后，官方服务确认发码成功，实际手机收到短信；取消或修改号码后不会继续旧请求的验证重试。
3. 提交收到的短信验证码后，Passport 认证及 Business 初始化均成功，形成可恢复的完整会话。
4. 验证组件加载失败、验证失败或重复挑战时显示准确错误，不误报已发送，不自动连续重试。

用户已报告本轮桌面人机验证及短信登录成功，见文末真实反馈；成功率及长期稳定性尚未量化。该配置来自固定版本的 Android 包，跨版本、浏览器、React Native 或小程序的兼容性需分别验证。短信登录不承诺解决与官方 App 的会话互踢。

在仓库根目录运行 `NINEBOT_AUTH_SOURCE=sdk pnpm dev`，然后选择「短信验证码」。已有应用实例应先由用户退出，避免单实例复用旧运行模式。
